# Plugin system: subprocess plugins with a declarative UI schema

Decision (a phase-2 feature, recorded now because the plugin ABI shapes the Daemon): papago plugins are standalone executables the Daemon runs as subprocesses — hashicorp/go-plugin style: manifest-declared, JSON/gRPC over stdio, OS-level isolation, any implementation language. Plugins observe lifecycle hooks (Agent/turn/Ask events), take actions (send prompts and follow-ups, answer Asks, create Agents, register additional Host tools), and may declare simple UI through a declarative schema that Clients render with built-in widgets, forwarding user events back to the plugin — never arbitrary client-side code. Shaped by the Paseo plugin-API survey (docs/digests/2026-10-20 Paseo plugin API.md): a plugin connects to the Daemon as an ordinary protocol Client with a reserved `plugin:<id>` identity — one API for GUI, CLI, and plugins, no plugin-only surface; its manifest declares capabilities (fs roots, network, agent control, UI slots) and the Daemon grants plugin sessions a reduced permission set, explicitly rejecting Paseo's capability-less, unsandboxed model; hooks pass ids instead of copied history and plugins fetch bounded pages (the lesson of Paseo's deprecated `turn_ended.timeline`); `before`-style hooks may edit typed requests (agent-create env/config) with a fixed timeout and ordered, no-merge semantics; plugins may append Timeline items (kind + version, size-capped) rendered through the same declarative schema, with an "unavailable" placeholder when a renderer is missing; the plugin API carries its own `apiVersion` independent of the app version, and removals are breaking changes. Distribution: a reviewed static registry of pinned artifacts (redirects disabled, self-hostable). Rationale: subprocess isolation protects Daemon stability and gives Go authors (the primary user) zero-friction authoring; the declarative UI schema provides plugin screens without embedding a UI runtime — the semantic-UI idea TSP pioneered, kept as papago's own contract instead of a dependency on a private protocol (ADR-0009). Rejected: embedded scripting (in-process risk, capability-API surface, limited languages), WASM (heavier author toolchain), code-level UI plugins (no cheap Go/MyGo equivalent of Paseo's daemon-compiled RN plugin machinery).
