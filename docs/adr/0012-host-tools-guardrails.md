# v0 ships agent-driven orchestration as host tools, with guardrails

Decision: papago registers six host tools on each Agent's omp session — `create_agent`, `send_agent_prompt`, `get_agent_status`, `list_agents`, `cancel_agent`, and `wait_for_agent` (blocking, capped at 60 s). Guardrails: caller-spawned Agents default to the caller's Workspace and carry an origin label; spawn depth is capped at 2 (deeper `create_agent` is refused); completion notification is delivered by injecting a follow_up into the caller (non-blocking, lands when that session settles) and coexists with `wait_for_agent`; any catalog entry can be disabled per Agent. Rationale: agent-dispatches-agent is a common ADE workflow, and omp's host-tools mechanism is the direct, structured callback path (no MCP adapter needed); the guardrails bound cascade depth, mutual-wait loops, and quota stampedes under the yolo default (ADR-0004).
