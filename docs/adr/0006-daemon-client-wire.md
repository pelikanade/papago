# Daemon↔Client wire: WebSocket + token, request/response with gated subscriptions

Decision: the Daemon speaks a single WebSocket JSON protocol over TCP (default bind 127.0.0.1, configurable; remote access means rebinding onto e.g. a tailnet IP — no relay or tunnel is built). Every connection authenticates with a token from day one. Semantics: requestId-correlated request/response; live updates (agent list, timeline) flow only after an explicit subscription; each Agent's Timeline carries a monotonic seq cursor plus an epoch that increments on agent restart or Session switch, so a reconnecting Client resumes from its cursor without server-side per-client state. Rationale: subscription gating keeps multi-client traffic proportional to what is watched; seq/epoch gives lossless catch-up; a token from day one avoids Paseo's retrofitted header-auth compatibility window.
