# papago does not speak TSP

The project was originally framed with a phase-2 TSP host: papago would implement the terminal side of the Tern Surface Protocol to render interactive omp at full fidelity. Decision: TSP is dropped from the entire project — no TSP host, no APC parsing on a pty, no dependency on the protocol anywhere. papago speaks omp's NDJSON RPC and nothing else. Rationale: TSP is v1-only, single-vendor, and belongs to a closed-beta product; its rendering layer is not normatively specified (~40 component kinds whose per-kind drawing is documented as Tern-internal, no conformance suite), and no host-side reference implementation exists — building and keeping a host would mean betting continuous effort on a private, fast-churning contract. The UX ambition survives without the protocol: the native Timeline, built purely from RPC events, keeps the TSP-style ideas (retained semantic cards, streaming text append, foldable tool bodies, todo/context HUD). The "sit inside interactive omp" use case is abandoned outright (ADR-0011: no embedded terminal); humans who want omp's own TUI run it in their own terminal, outside papago.

Supersedes the TSP-host phase and attach-semantics paragraph of ADR-0002; RPC-as-control-substrate remains in force.
